局域网共享 Agent 记忆库

基于 engram v1.20.0 的补丁与只读管理面板： 一个服务进程独占 SQLite，网段内多个 agent 经 HTTP + Bearer token 读写同一份库。

Go 1.26+ 补丁 ~230 行 · 仅改 cmd/engram/main.go MCP 默认端口 7440 · 面板 7441 MIT
阅读 README 快速开始 配置参考 CONFIG.md

说明：本页为文档化静态展示，截图与动图来自仓库 docs/assets。 实际管理面板需自行部署 engram-admin 并连接 Go API，此处不提供可交互的假仪表盘。

项目组成

上游 engram 的 MCP 仅支持 stdio（一 agent 一进程、同机限定）。 engram-lan 用两个独立组件解决局域网共享，不带 --http 时补丁行为与上游 100% 一致。

组件 作用
patches/engram-lan-mcp-v2.patch 为 engram mcp 增加 --http <addr>（mcp-go streamable HTTP，同一 MCPServer，工具未改） + 多账号 token 名单文件鉴权（mtime 热重载）。
admin/ 零依赖 Go 二进制：账号体系（管理员 / 成员）、按人签发/吊销 token（无需重启服务）、 只读 Memory 浏览（FTS5 全文搜索）、全局统计大盘。

与上游 engram cloud serve（Postgres 同步、N 份本地 SQLite 最终一致）不同， engram-lan 是单库共享语义——README 中描述为团队知识库场景的定位差异。

架构

agent A ──┐
agent B ──┼── HTTP + JSON-RPC（Bearer token）──▶ engram-mcp :7440
agent C ──┘                                      │  补丁 v2：token 名单鉴权
                                                 │ （mtime 变化自动热重载）
                                                 ▼
                                          store.Store（单进程持有）
                                                 ▼
                                          SQLite WAL + FTS5
                                                 ▲
你 ── 浏览器 ──▶ engram-admin :7441 ─────────────┘
                 （登录、token 管理、只读 memory + 统计）
  • SQLite WAL 与本地文件锁 WAL 需要 -shm 共享内存与本地锁语义；网络盘会损坏数据库，因此必须单进程独占文件，其余客户端走网络。
  • 面板只读由 OS + 代码双重保证 面板用户组权限仅读库目录/文件，且以 mode=ro 打开 SQLite；即使面板被攻破也无法写入记忆库。
  • token 名单是唯一写面 面板原子写入 tokens.json；engram 按 mtime 热重载；文件丢失或损坏时 fail-closed（全部 401）。

Token 签发 / 吊销

名单文件热重载；吊销后 MCP 侧立即 401，无需重启 engram-mcp。

全文搜索

面板调用 GET /api/memories?q=…，底层 FTS5 + BM25 排序（见 CONFIG.md API 说明）。

Admin / 搜索 / 统计工作流

基于 admin/static/index.html 导航与 docs/CONFIG.md 记录的 API，面板能力如下（需自行部署后使用）。

登录与角色

首次启动用 ENGRAM_ADMIN_PASS_BCRYPT 播种管理员。 成员用用户名密码登录；会话带角色，/api/users* 与 /api/tokens* 仅管理员（成员得 403）。

成员：我的 Key

一键生成/重新生成个人 agent token（旧 token 立即失效）。 提供 Claude Code、Codex、Cursor、Gemini CLI 的配置片段与复制按钮（URL 来自 ENGRAM_ADMIN_MCP_URL）。

Memory 浏览与搜索

GET /api/memories 分页浏览；带 q 参数时走 FTS5 搜索。 GET /api/memories/{id} 查看完整记录。面板对 engram.db 只读打开。

统计大盘

/api/stats/overview 汇总指标； /api/stats/timeseries 按日写入量； /api/stats/breakdown 按类型/项目/scope； /api/stats/topics 按 revision 排名的 topic_key。

管理员：用户与 Token

用户管理：创建/禁用/重置密码/删除（删除连带吊销 token）。 Token 管理：签发、吊销、更新备注；完整 token 仅在创建/重新生成时返回一次。

安全模型（文档摘录）

以下内容摘自 README / CONFIG.md，描述已实现的机制，非额外安全承诺。

层 机制
网络鉴权 按人 Bearer token；constant-time 比对；名单热重载；吊销/损坏 → 401（fail-closed）；401 记录来源 IP。
面板登录 独立 SQLite 账号库；bcrypt；内存会话（HttpOnly + SameSite=Strict）；登录限流 5 次/5 分钟/IP。
库完整性 面板文件系统只读 + mode=ro；engram-mcp 为唯一写入者。
同机隔离 库目录 750、文件 640、组 engram；仅面板用户在组内。
传输 局域网内明文 HTTP；README 明确建议勿将 7440/7441 暴露到内网之外。未内置 TLS。

已知限制

  • 写入项目名须服务端可解析 需 --project 默认或预先 seed 的项目；服务端无客户端 cwd。读取不受此限。
  • 共享库全员可读 持有 token 者可读写同一知识空间；私人记忆应留在本机 engram。
  • 面板会话在内存 面板重启需重新登录；agent token 与 SQLite 数据不受影响。
  • 部署环境 README 快速开始面向 Linux 服务器与 Go ≥ 1.26；需自行配置 systemd 与文件权限（见 CONFIG.md）。
